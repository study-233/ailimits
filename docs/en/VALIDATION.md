# QuotaBar validation

## Automated checks

```powershell
cargo +stable-x86_64-pc-windows-msvc fmt --all -- --check
cargo +stable-x86_64-pc-windows-msvc clippy --locked --all-targets -- -D warnings
cargo +stable-x86_64-pc-windows-msvc test --locked
cargo +stable-x86_64-pc-windows-msvc build --locked --profile release-min --bins
```

The tests cover configuration migration, independent malformed fields, quota window selection, missing data, stale/estimated status, 0/100% rendering, source-data immutability, all six display combinations and 100/125/150/200% scaling. Existing taskbar geometry tests cover drag position, lock-compatible placement, crowded taskbars and DPI changes.

## Visual and native interaction checks

Run these independently: the native test temporarily changes the process-wide UI language and opens a test window without reading or writing the user's configuration.

```powershell
cargo +stable-x86_64-pc-windows-msvc test --locked export_quotabar_previews -- --ignored --test-threads=1
cargo +stable-x86_64-pc-windows-msvc test --locked native_preferences_preview_save_cancel_and_dpi -- --ignored --test-threads=1
```

Output: `target/quotabar-preview/`. Preview values are synthetic (93% and 68%); images are generated by the production renderer. Native screenshots cover English/Chinese preferences and the expanded bar controls. The native check validates preview events, Save, Cancel/close and DPI messages. Inspect the screenshots after UI changes.

Manually exercise taskbar auto-hide/full-screen transitions and multiple monitors on the intended Windows configuration. These depend on the live shell and are not simulated by the renderer tests.

## Performance

No new dependency, request loop, animation timer, font download or web runtime is added. Panel/tray redraw caches include selected periods and their full data states; appearance and theme changes invalidate them. Settings window fonts and GDI brushes are released when the window closes.

`bench/perf_audit.ps1` can collect CPU, memory and GPU counters where WMI permissions allow. If WMI is denied, record process CPU-time deltas and working/private bytes instead; do not report unavailable GPU counters as zero. Compare the same presentation, language, hover state and warm-up time because loading Windows CJK fonts affects the working set.

## Packaging

`tools/package-release.ps1` verifies Cargo/installer/PE versions, x64 binaries, portable archive paths and checksums. Both packages include the README's local documentation and images. The installer retains the old AppId and data paths, changes its display name and deletes only known old shortcuts.

The updater accepts the new `.exe` asset name and continues to require a newer version and a valid SHA-256 digest. The bootstrap installer also accepts old `AiLimits-Setup-*` assets until a QuotaBar release is published. Public release publishing and the online repository description are separate from local packaging.

The earlier capture helper forced a repaint and the menu check did not open submenus. Those results did not establish correctness of initial or interactive painting. The capture helper now drains normal queued messages without invalidating windows. The menu test traverses submenu paths and checks rendered text pixels. Desktop tests require the normal interactive desktop; reading a popup DC on the restricted desktop can capture the underlying desktop instead.

During repair, the settings matrix and a second-level menu check ran successfully. Full menu acceptance was stopped when the user requested to perform UI acceptance themselves. Final visual acceptance is therefore pending the user's review; no claim of exhaustive live interaction or physical monitor/DPI coverage is made. Automated coverage includes Pro/non-Pro/unknown subscription parsing, tooltip-only filtering across both entry points, missing weekly quotas, old-cache compatibility, fresh plan replacement, and preservation of plan metadata during stale-data estimation.

Final non-interactive checks passed: 124 automated tests, formatting, Clippy with warnings denied, and `cargo build --locked --release --bin ailimits`. The acceptance executable is `target/release/ailimits.exe`; the running older release-min process was not replaced or restarted.

## Preferences wheel repaint repair (2026-09-17)

Wheel and focus scrolling now skip unchanged offsets and move existing controls in a deferred batch without resizing or resetting them. Scroll repaint requests no longer erase the window; the parent background and previews are rendered into a back buffer and presented together. Two regressions cover stationary/boundary scrolling and clamping at 100/125/150/200% scale. All 126 non-interactive tests, formatting, Clippy with warnings denied, and the release-min build passed. The acceptance copy is `target/scroll-fix/QuotaBar.exe`; its SHA-256 matches the build. Per user request, the existing application was not stopped and no desktop interaction tests or automatic launch were performed. Visual acceptance remains with the user.

## Tray and taskbar appearance synchronization (2026-09-17)

The tray had overridden the weekly color with neutral ink, ignored the selected bar style, and reduced dual-period graphics to one value. It now shares the panel's period colors, ring/bar primitives and period selection, with geometry adapted to native icon sizes. Explicit Number mode retains its compact presentation and now shares numeric color and weight. Both appearance setters normalize the same draft; Preview/Save/Cancel already update both surfaces.

A single hover-summary function now supplies both surfaces, including the legacy tray's Codex summary. It shares period selection, line order, reset countdown and update age. The observed `prolite` response is explicitly recognized alongside `pro`, including cached snapshots and a primary weekly window with no secondary window. Unknown plan strings are not inferred from metric count. This remains tooltip-only filtering.

All 128 non-interactive tests passed, along with `fmt --check`, Clippy for all targets with warnings denied, `git diff --check`, and the release-min build. Regression coverage checks actual period-colored pixels in tray and panel renders for both shapes, all three period selections, both themes and 16/20/24/32-pixel tray sizes; switching shape, numeric color or numeric weight changes the rendered result. Existing layout tests cover 100/125/150/200% scaling. Offscreen production exports were inspected in light and dark themes (`target/quotabar-preview/synchronized-*.png`). These exports do not open or manipulate desktop windows.

The acceptance binary is `target/appearance-sync/QuotaBar.exe`, copied from `target/release-min/ailimits.exe` with matching SHA-256. The old `target/scroll-fix/QuotaBar.exe` process was left running for the user to exit before opening the new binary. Per the user's preference, no automatic launch or live desktop acceptance was performed.


## Complete quota panel — v0.3.0 (2026-09-17)

The popup now has an independent, stable five-module layout. Base quota polling remains in the existing scheduler; on-demand App Server reads add reset credits and daily Token buckets. There is no WebView, database, chart framework or resident Codex helper. Existing dependency features add Tokio pipe I/O and Win32 job/thread APIs.

The automated suite covers time ratios, pace, missing fields, account isolation and rotation, count-only/zero/unavailable reset opportunities, observation deduplication/anchors, token upserts, gaps, reset boundaries, retention and configuration migration. A local PowerShell protocol fixture verifies bounded reads, timeout and cleanup of a real child process tree without Codex credentials or network access.

Run these native checks separately (Tao owns one event loop per process):

```powershell
cargo +stable-x86_64-pc-windows-msvc test --locked native_complete_panel_hidden_render_and_scroll -- --ignored --test-threads=1
cargo +stable-x86_64-pc-windows-msvc test --locked native_panel_settings_hidden_controls -- --ignored --test-threads=1
```

These checks create hidden, isolated production Win32 windows. They exercise 96/120/144/192 drawing scale, scroll, fixed controls, chart ranges, cached bitmap reuse, timer removal, checkboxes, drag handles, arrow reordering, defaults, all-hidden state, save/cancel events and serialization. Rendering uses their own memory DCs and explicit child coordinates, never screenshots of another application or the desktop. Synthetic render artifacts are in `target/quotabar-complete` and selected samples in `docs/images`.

Hidden controls and synthetic DPI do not establish actual foreground/focus behavior, mixed-DPI monitor transitions, shell/taskbar auto-hide, or per-account availability of live service extensions. Final visual and interactive acceptance belongs to the user. This build does not replace or restart the installed running app.

Production artifact: `target/release-min/ailimits.exe`. Quit the running version before opening it because QuotaBar is single-instance.
