What QuotaBar reads and stores.

QuotaBar is a native Windows 11 app for viewing remaining Codex quota on your taskbar. It runs on your computer, with no QuotaBar account or intermediary server. Network access is used for provider data and release updates, as described below.

Authentication and base quota

Base quota reads reuse existing credentials without refreshing or rotating CLI tokens. Sources depend on the enabled provider:

  • Codex — the official CLI login in auth.json under CODEX_HOME, or %USERPROFILE%\.codex by default.
  • Claude — the Claude Code login in %USERPROFILE%\.claude\.credentials.json, and an available status-line snapshot.
  • Copilot — the token returned by gh auth token.
  • Antigravity — its session in Windows Credential Manager or a supported legacy Gemini CLI login.

Missing or expired authentication is shown as unavailable. Manually entered keys or usage tokens are stored in Windows Credential Manager, not in the settings file.

Optional local Codex App Server

Enabled reset-opportunity and daily Token modules read through the installed official Codex App Server. QuotaBar checks the account identity before and after the read and does not combine data for an unconfirmed account. Opening the panel refreshes enabled extension modules when their cache is older than five minutes; manual refresh also updates them.

The official CLI manages its own authentication during these reads, so its behavior is separate from QuotaBar’s read-only base quota requests. QuotaBar does not request login, logout, model turns or consumption of reset opportunities. The helper exits after reading; a 25-second deadline and Windows job object clean up its process tree.

Where requests go

Base provider requests go over HTTPS to the provider endpoints: api.anthropic.com, chatgpt.com, api.github.com and daily-cloudcode-pa.googleapis.com. Only enabled providers are polled. Optional Codex App Server reads use the official CLI’s service connections. Windows static-proxy settings or the selected direct-connection setting govern QuotaBar’s requests.

When automatic updates are enabled in an installed copy, QuotaBar checks GitHub for study-233/ailimits releases and verifies downloaded updates. Portable copies update manually. This distribution is not published to Microsoft Store or package managers.

QuotaBar does not send analytics, crash reports or advertising data to a project server.

What stays on your computer

  • Settings — %APPDATA%\AiLimits\config.toml, including appearance, provider selection and panel layout; no secrets.
  • Last readings — provider-cache.json beside the settings, for displaying marked cached values when fresh readings are unavailable.
  • Quota and Token history — quota-history.json beside the settings, retaining 30 days and separated by opaque SHA-256 account keys, without tokens or email addresses. Quota observations record real local readings, including while the history module is hidden. Token buckets use service-provided dates; missing dates do not become zero.
  • Legacy usage history — history.jsonl may also be present beside the settings for existing provider history.
  • Optional secrets — Windows Credential Manager entries under the ailimits service.
  • Diagnostic log — ailimits.log beside the settings when file logging is enabled with AILIMITS_LOG or RUST_LOG.

History does not backfill quota readings from before installation. Hiding a module does not delete its stored history.

The Diagnostics menu can copy a report at your request. It excludes tokens, emails, account identifiers, proxy addresses, local paths and raw error text. Reports are not uploaded automatically.

Removing QuotaBar

The installer’s uninstaller removes QuotaBar’s settings directory, cache, history and app-created Credential Manager entries. For a portable copy, removing the extracted files does not remove settings under %APPDATA%\AiLimits or manually stored credentials; remove those separately if desired. Existing CLI logins are not owned by QuotaBar and are not deleted by its uninstaller.
